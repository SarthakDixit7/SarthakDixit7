<details>
<summary><strong>Production hybrid RAG blueprint</strong></summary>

**Ingestion:** semantic chunking (512 tokens, 15% overlap) with parent-child pairing (1024/256), deduplication, and PII masking before indexing.

**Retrieval:** parallel BM25 and dense BGE embeddings, fused using Reciprocal Rank Fusion (RRF), then cross-encoder reranking to the top five passages. A lightweight knowledge graph links policies, complaint categories, and past resolutions.

**Generation:** fine-tuned Llama and Mistral checkpoints, citation-enforced prompts, and Pydantic structured output contracts.

**Evaluation:** context precision **0.87 → 0.93** after reranking, recall@10 **0.91**, faithfulness **0.89**, answer relevancy **0.91**, and p95 end-to-end latency **1.9 s**. The system supported **10,000+ monthly queries** and reduced complaint-resolution time by **40%**.

</details>

<details>
<summary><strong>Agents, reliability, evaluation and governance</strong></summary>

- **Agent workflows:** LangGraph state machines with tool nodes for ticket lookup, policy retrieval, and CRM writes; conditional edges, retries, fallbacks, and human-handoff states.
- **Tool integration:** MCP servers exposing CRM, ticketing, and policy tools through Pydantic JSON-schema contracts; LangSmith traces for replay and per-node inspection.
- **Release quality:** 1,200 curated Q/A/context triples scored with Ragas, DeepEval, and GPT-4o LLM-as-a-judge; nightly CI regression runs gate model and prompt releases.
- **Responsible operations:** PII redaction before fine-tuning and inference, role-based model access, audit trails, dataset lineage, and factuality guardrails.
- **Inference optimisation:** vLLM continuous batching and PagedAttention; quantisation comparisons across FP16, AWQ, GPTQ, and GGUF; Redis/GPTCache semantic caching.

</details>
